# Koko ttcut

從原始桌球比賽影片到可發布成片：以回合候選偵測協助找球、用鍵盤快速人工 Review，加入比分板與精彩球，最後在本機完成輸出。

Koko ttcut 是 [MikaDD-TW/ttcut](https://github.com/MikaDD-TW/ttcut) 的增強 fork。它保留原專案實用的手動標記事件與 FFmpeg 成片基礎，再加入 Review 工作區、多段影片與多場賽事製作流程。專案延續原本的 [MIT 授權](LICENSE)。

[English](README.md) · **繁體中文**

Koko ttcut 完全在本機執行；程式本身不要求帳號，也不需要把原始影片上傳到雲端服務。

## Koko ttcut 可以做什麼

| 功能 | Koko v1.4 工作流程 |
| --- | --- |
| **回合候選輔助偵測** | 依選定 ROI 內的視覺活動尋找候選，音訊只作為信心輔助；偵測結果必須由人 Review，不會自動計分。 |
| **Rally Review Mode** | 依時間順序快速確認候選、計分、跳過與前後巡覽。 |
| **手動補漏球** | Detector 漏球時，不必離開 Review；在真正發球時間按 `S`，再按 `A` 或 `B`。 |
| **Review Workspace** | 把權威比分 HUD、下一球「應發球」提示、候選進度、影片與事件歷史集中在同一工作區。 |
| **多段影片同一場比賽** | 把連續的 2～N 段影片視為同一條全域時間軸。 |
| **Koko 彩色比分板** | 依人工確認的事件產生成片比分板；人工計分永遠是權威來源。 |
| **精彩球標記** | 在 Review 或一般編輯時標記已完成回合，供後續集錦使用。 |
| **賽事精彩集錦 Builder** | 從多場比賽挑選、排序精彩球，合成一支賽事集錦。 |
| **片頭與封面** | 使用自然原片製作 3 秒片頭，並依設定自動產生可選的 YouTube 封面；各列文字獨立縮小並維持單行。 |
| **結構化輸出** | 有規則地整理 MP4、可選封面與 `ttcut-data/*.tags.json`。 |

原版 ttcut 的核心是直接用 `S`／`A`／`B` 手動標記。Koko 完整保留這條可靠路徑，再加上候選偵測、人工 Review、多段影片與賽事層級輸出。它不是「全自動剪球」或保證零漏球的 AI：候選是否為真正回合由使用者判斷，比分也只以人工輸入為準。

## 快速上手

### 環境需求

- **Python 3.8 以上**
- **FFmpeg**，而且要有 `libass` 支援（比分板使用的 `subtitles` 濾鏡需要它）

目前文件支援的安裝方式如下：

```bash
# macOS
brew install ffmpeg

# Windows —— 到 https://www.gyan.dev/ffmpeg/builds/ 下載
# 把 ffmpeg.exe 放在腳本旁邊，或用 --ffmpeg "C:\ffmpeg\bin" 指定資料夾

# Debian / Ubuntu
sudo apt install ffmpeg
```

ttcut 會依序尋找 `PATH`、腳本旁邊與 Windows 常見安裝位置。Apple Silicon Mac 若已安裝含字幕支援的版本，也會優先使用 `/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`。沒有 FFmpeg 時仍可標記事件及匯出 JSON，但不能製作成片。

### 啟動程式

```bash
# 繁體中文介面
python3 ttcut_v2_3.py

# 英文介面
python3 ttcut_v2_3_EN.py
```

程式會在 `127.0.0.1` 啟動本機服務並開啟瀏覽器介面。

1. 載入單段錄影；同一場比賽有連續多個檔案時，選 **載入多段影片…**。
2. 填入兩位選手、先發球者與賽制。
3. 可以直接用 `S`、`A`、`B` 手動標記；也可以框選 ROI、分析回合，再進入 **Rally Review Mode**。
4. 核對比分與「應發球」提示；完成的回合若要收入集錦，按 `H` 標記精彩球。
5. 選擇 Koko 或 ttcut 原版比分板，以及可選的統計看板、片頭、封面、畫質與輸出整理方式。
6. 由 FFmpeg 在本機製作成片。

## 核心流程：候選偵測與 Rally Review Mode

### 回合候選輔助偵測

先停在能清楚看見目標球桌與兩位選手的畫面，框選主要活動區域 ROI，再按 **分析回合**。Detector 會依 ROI 內的動作與輔助音訊信心提出候選區間；音訊不能單獨建立回合，也不能判斷由誰得分。

來源片段解析度不同時，必須逐段框選 ROI；解析度相同但鏡位移動時，可啟用逐段 ROI。4K／60 fps HEVC 完整分析可能需要幾分鐘。

候選可能誤判，也可能漏掉真正回合。低信心候選仍會保留給人工判斷；只點選或預覽候選不會改動比賽事件。

### Rally Review Mode

Review Mode 會從第一個未審候選開始，停在該候選前 0.8 秒；跨檔時不會越過來源片段起點。

1. 按 `Enter`，把目前 detector 候選確認為發球。預設會接著自動播放。
2. 該球結束時按 `A` 或 `B`。這會走一般編輯器相同的權威事件與計分路徑。
3. 候選不是回合時按 `X`；用 `[`／`]` 前後巡覽。
4. Detector 漏球時，跳到真正發球時間按 `S`，再用 `A` 或 `B` 完成手動回合。手動補漏球不會改變候選進度。
5. 按 `H`，切換相關已完成回合的精彩球標記。

專用 Review Workspace 的固定 HUD 會顯示目前局號、雙方局數與分數、下一球應由誰發球（`🏓 應發球：球員`）及候選進度。影片下方保留可獨立捲動的事件歷史。HUD 直接使用一般編輯器相同的 Python 計分結果，不另存一套比分或輪替狀態。

Detector 候選與 Review 進度只存在目前 session，不會寫入 tags JSON。重新分析、開新比賽或重啟程式後會清除；已確認的比賽事件與精彩球標記則照常保存在標記檔。

## 一般比賽成片

### Koko 比分板與權威計分

**比分板樣式**可選新標記預設的 **Koko 彩色表格**，也可切回 **ttcut 原版**以維持相容。Koko 樣式位於成片左下角，每位選手各一列：深色姓名欄、藍色 `#19559B` 局數欄與綠色 `#14703F` 分數欄。長姓名只會在姓名欄內縮小；成片比分板刻意不顯示發球記號。

比分板只由人工確認的發球、得分與換局事件推導；候選信心不會改變比分。發球輪替依先發球者與賽制計算：一般每人兩球，deuce 後每球換發，新一局由另一位先發。

### 片頭與 YouTube 封面

一般比賽可加入 3 秒片頭，背景使用原片開頭的自然畫面與音訊；比分板從正片開始才出現。賽事、組別、選手、學校／附加資訊預設使用一致的基準字級，只有超出各自寬度的列或左右區塊才縮小，並維持單行。啟用封面時，程式會自動產生 1280×720 YouTube 封面，並使用同一套字體與縮放計算。

### 片尾統計看板

可選的統計看板會凍結最後一格畫面，顯示各局比分、總得分數、發球得分率與最多連續得分。發球得分率取決於正確的發球事件；若 `S` 漏標或標錯，推導出的輪替與得分率也會失真。

## 精彩球與賽事精彩集錦 Builder

完成一球後按 `H` 可切換精彩球；也可以先選取歷史得分列，或直接按該列星號。標記會存進該 point event 的 tags JSON。

按 **建立賽事精彩集錦…** 並選擇賽事根目錄，即可進入獨立 Builder。它會遞迴找出新版 `*/ttcut-data/*.tags.json` 與舊版比賽資料夾內的 `*.tags.json`，收集有效的 `highlight: true` 得分事件。可以預覽、取消勾選並調整比賽與球序，不會修改來源 tags。

Builder 會輸出一支 MP4，內容包括：

- 使用第一個已選精彩球自然動態原片的 3 秒賽事片頭；
- 依 Review 順序直接串接的精彩球，不插入場次分隔卡；
- 每球都依權威事件狀態顯示 Koko 比分板；
- 可選的 1280×720 封面，使用相同自然背景與字體規則；
- 一份精簡的 `ttcut-data/*.highlights.json` 專案 manifest。

若所有來源規格一致，會保留共同解析度與影格率；混合規格則統一成 1920×1080、30 fps，保持畫面比例並補邊。

## 多段影片與輸出整理

多段來源共用一條連續全域時間軸；候選時間、比賽事件、跳轉與剪點都使用這個時間。若解析度、影格率、編碼或音訊規格不同，介面會先警告，再由同一次 FFmpeg 成片流程逐段調整，不會預先建立合併原片。原始錄影不會被搬移或重新命名。

選擇 **每場比賽建立子資料夾** 時，輸出結構如下：

```text
<目的地>/
└── <檔名>/
    ├── <檔名>.mp4
    ├── <檔名>.thumbnail.jpg          # 有啟用封面時
    └── ttcut-data/
        └── <檔名>.tags.json
```

自動輸出若遇到同名比賽資料夾，會加上 `_2`、`_3`。選擇 **同一資料夾** 則保留舊版平放方式。製作前的輸出預覽會列出影片、封面與 tags 的預定路徑。

## 鍵盤快捷鍵

游標正在輸入欄位或操作互動控制時，不會觸發快捷鍵。

| 按鍵 | 一般編輯器 | Rally Review Mode |
| --- | --- | --- |
| `Space` | 播放／暫停 | 播放／暫停 |
| `←`／`→` | 逐格 | 逐格 |
| `Shift` + `←`／`→` | 前後 1 秒 | 前後 1 秒 |
| `Option`／`Alt` + `←`／`→` | 前後 5 秒 | 前後 5 秒 |
| `S` | 在目前播放時間加入發球 | 在目前播放時間手動補標發球，不依附候選 |
| `Enter` | — | 把目前 detector 候選確認為發球 |
| `A`／`B` | A／B 得分 | 完成目前候選回合或手動補漏回合 |
| `X` | — | 跳過目前候選 |
| `[`／`]` | — | 上一個／下一個候選 |
| `H` | 切換已選或最近完成回合的精彩球 | 相同 |
| `N` | 換局 | 換局 |
| `Z` | 復原最後一筆事件 | 復原最後一筆事件 |
| `1`／`2`／`3`／`4` | 0.5×／1×／1.5×／2× 播放 | 相同 |

手動 `S` 尚未計分時，必須先按 `A`／`B` 完成，或用 `Z` 復原，才能繼續用 `Enter` 或 `X` 審核候選。已確認發球的候選也不能直接跳過，必須先復原該發球。

## 賽制與統計

| 設定 | 用途 |
| --- | --- |
| 每局 *n* 分 | 預設 11 分；舊制可設為 21。 |
| 標準／封頂 | 標準制須贏兩分；封頂制在 10:10 後抵達設定上限即結束。 |
| 起始局數 | 接續先前已錄完的局數。 |
| 讓分 | 起始分數，可套用每一局或只有第一局。 |

讓分會顯示在比分板上，但不影響發球輪替，也不列入統計看板的實際得分。

## 命令列重新成片

已有 tags 檔案時，可不開介面直接重新成片：

```bash
python3 ttcut_v2_3.py match.tags.json match.MOV
python3 ttcut_v2_3.py match.tags.json match.MOV --quality max --stats --stats-hold 3
python3 ttcut_v2_3.py match.tags.json match.MOV --dry-run
```

主要參數包括 `--out`、`--lead`、`--tail`、`--min-cut`、`--stats`、`--quality`、`--encoder`、`--fps`、`--hdr`、`--size`、`--hwaccel`、`--font`、`--ffmpeg` 與 `--scoreboard-style koko|ttcut`。請執行 `python3 ttcut_v2_3.py --help` 查看權威完整清單。最短剪點預設為 2.5 秒。

## 標記檔與實作說明

標記檔是一般 JSON，記錄來源檔、片段偏移、選手、賽制、比分板樣式、片頭資料與時間事件。精彩球旗標直接存在得分事件上，例如：

```json
{"t": 25.0, "type": "point", "winner": "B", "highlight": true}
```

舊版標記檔仍可讀取，缺少的區塊會套用相容預設值。多段 tags 重新開啟時，若有來源片段遺失，會顯示缺少的檔名。

成片由 FFmpeg 完成。保留區間會直接從來源影片選取，不先產生合併原片；比分板以 ASS 字幕產生並燒入影片；比分由本機 Python 統一計算，因此編輯器 HUD 與最後成片共用同一套邏輯。
