# ttcut

把一整段桌球比賽錄影變成節奏緊湊的成片：剪掉撿球、疊上常駐計分板，片尾再補一張數據統計看板。

[English](README.md) · **繁體中文**

本機執行，不用註冊、不上傳；影片從頭到尾都待在你自己的電腦裡。

## 這個工具做什麼

回合標記一次做完，剩下的交給 ttcut：

- **剪掉空檔。** 從得分到下一次發球之間——撿球、走回來、擦汗——全部剪掉。四十分鐘的錄影通常會收到十二到十五分鐘。
- **燒上計分板。** 名字、局數、當局比分常駐在角落，數字由你的標記推導出來，不用另外手動輸入。
- **片尾收在統計看板。** 可選：凍結最後一格畫面，疊上各局比分表與雙方三個指標。
- **順手標記精彩球。** 每球按完 `A` 或 `B` 後可按 `H` 切換精彩球，標記會留在同一份 JSON，供之後製作賽事集錦。

標記是刻意手動的。沒有球體追蹤會失準，也沒有模型要下載——發球按 `S`、得分按 `A` 或 `B`，速度跟看完整場比賽差不多。

## 環境需求

- **Python 3.8 以上**
- **ffmpeg**，而且要含 `libass`（畫計分板的 `subtitles` 濾鏡需要它）

```bash
# macOS
brew install ffmpeg

# Windows —— 到 https://www.gyan.dev/ffmpeg/builds/ 下載，
# 把 ffmpeg.exe 放在腳本旁邊，或用 --ffmpeg "C:\ffmpeg\bin" 指定資料夾

# Debian / Ubuntu
sudo apt install ffmpeg
```

ttcut 會依序找 `PATH`、腳本旁邊、Windows 常見安裝位置。找不到也還能標記和匯出 JSON，只是沒辦法算圖。

## 快速上手

```bash
python3 ttcut_v2_3.py
```

它會在 `127.0.0.1` 開一個本機服務並打開瀏覽器。接著：

1. 單段錄影按 **載入影片**；同一場分成多個檔案時按 **載入多段影片…**。系統對話框可一次選 2～N 段，初次載入依自然檔名排序；畫面會顯示各段長度、全域起訖與總長。開始標記前可用 ↑／↓ 調整順序。
2. 填兩位選手的名字，選誰先發球。
3. 一邊播一邊標：發球觸拍的瞬間按 `S`，分數結束時按 `A` 或 `B`。這球值得收進集錦時再按 `H`；再按一次可取消。
4. 想要片尾統計看板就勾 **數據統計**。
5. 品質選 **標準**（一般成片建議）；**極致（CPU，非常慢）** 適合特別要保存的版本。
6. 視需要勾 **加入片頭**，填入賽事名稱、組別，以及左右選手與各自學校；也可勾 **同時輸出 YouTube 封面**。若上方選手名稱寫成 `許宸愷（光復國小）`，可按 **從選手資料帶入**。
7. 在 **輸出整理方式** 選擇「每場比賽建立子資料夾」（新比賽預設）或「同一資料夾」，再按 **製作成片**。六個片頭欄位完整時，檔名為 `賽事名稱_組別_選手A(學校A)VS選手B(學校B).mp4`，即使未勾「加入片頭」也適用；欄位不完整時回退為 `<原檔名>.cut.mp4`。**另存為…** 可選目的地根目錄與檔名。

片頭欄位修改時，介面會即時顯示預計輸出的 MP4、封面與標記路徑；一旦手動選了「另存為…」，繼續修改片頭也不會改掉所選檔名。自動命名保留中文與一般標點，只將檔名不安全字元及控制字元換成 `_`，合併連續底線並清理首尾空格、點與底線。

「每場比賽建立子資料夾」會輸出 `<目的地>/<檔名>/<檔名>.mp4`、`<目的地>/<檔名>/<檔名>.thumbnail.jpg`（有勾封面時），標記則放在 `<目的地>/<檔名>/ttcut-data/<檔名>.tags.json`。`ttcut-data` 是一般可見資料夾。自動輸出若已有同名比賽資料夾，資料夾與內部檔案一同加 `_2`、`_3`。手動另存為若選到既有比賽資料夾，畫面會要求另選檔名。「同一資料夾」保留舊版平放行為；自動輸出遇到同名 MP4 也會加 `_2`、`_3`。原始 DJI 檔案不會搬移、重新命名或複製。

多段影片共用一條連續時間軸，候選、事件、點選跳轉與剪點都用全域時間。若解析度、影格率、編碼或音訊規格不同，介面會警告，成片時在同一次 FFmpeg 執行中逐段調整，不會預先產生合併原片。解析度不同時，分析回合前必須逐段框選 ROI；解析度相同但鏡位改變時，可勾選「鏡位不同時逐段框選 ROI」。標記 JSON 記錄各段來源路徑與時間偏移；重新讀入時若缺檔，會顯示該檔檔名。

剪下一場時按 **新增比賽**，會清空上一場的來源影片、標記、比分、候選、自訂輸出路徑與片頭文字，但保留輸出整理方式、品質、比分板樣式、片頭時長及剪輯預設。有未匯出的標記時會先確認。按 **結束 ttcut** 可關閉本機服務；終端機 `Ctrl-C` 仍可使用。單純關閉瀏覽器分頁不會停止服務。

片頭預設 3 秒，使用原片開頭畫面與音訊；比分板從正片開始才出現。書法風會優先找本機的 `Xingkai TC`，再回退至 `Kaiti TC`、`Songti TC`、`PingFang TC`，不會下載或打包商業字型。可在「片頭字體風格」欄輸入已安裝的字體名稱。Mac 若一般 `ffmpeg` 沒有 `subtitles` 濾鏡，程式會優先使用 `/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`。

新版片頭的賽事與組別置中，選手 A／B 分列左右，學校各自對齊所屬選手。長名字只會縮小自己的字級。舊版四行標記 JSON 讀入後，若對戰與學校可明確拆分會轉入新版欄位；否則保留原四行版面供編輯，不會遺失文字。

### 影片比分板樣式

上方的 **比分板樣式** 可選 **Koko 彩色表格**（新標記預設）或 **ttcut 原版**。這個選項只影響最後成片，不改右側編輯預覽、比分規則或剪接。樣式會存進標記 JSON 的 `scoreboard.style`；舊標記若沒有這個欄位，讀入後維持 ttcut 原版。

Koko 樣式在影片左下角顯示兩列「姓名｜局數｜分數」。姓名欄是深色半透明底，局數欄是藍色 `#19559B`，分數欄是綠色 `#14703F`，文字均為白色。欄位尺寸固定，較長姓名只縮姓名字級，最小 22 px（以 1080p 為基準）；超長內容會限制在姓名欄內，避免蓋住數字。影片比分板不顯示發球標記；編輯介面的發球提示仍照原本運作。命令列可用 `--scoreboard-style koko` 或 `--scoreboard-style ttcut` 覆寫 JSON。

### 實驗功能：ROI 回合候選 v0.2.3

這個分支額外放了小型、可撤回的回合偵測原型。它不會判斷誰得分，也不會自動修改標記：

1. 載入影片並停在能清楚看到本桌與兩位選手的位置。
2. 展開右側的 **回合候選 · ROI v0.2.3**，按 **框選 ROI**。
3. 在影片上拖曳，盡量只框住中央目標球桌與兩位選手的活動範圍，排除左右、後方其他桌。
4. 按 **分析回合**。點候選區間或編號可跳到候選起點預覽；確認時間合理後才按 **確認發球**。點候選不會新增標記。
5. 每球勝方仍照原本方式按 `A` 或 `B`，人工判斷是唯一權威。

候選的開始／結束、長度、ROI motion 平均值與峰值、左右活動平衡、視覺強／弱取樣格數、輔助音訊數量和總分都會列出。長候選若有持續的 ROI 動作低谷，且前後都有足夠視覺活動、後段明確重新活動，會嘗試切分；短暫低谷且擊球聲持續時則不切。每個候選會顯示切點、低谷分數／持續時間、低谷中的音訊數量及切／不切的原因。音訊不能單獨建立回合或決定得分者。診斷列也會顯示 ROI 的 `x,y,w,h`，方便下次用同一範圍重現結果。`rally_detection.py` 必須和 `ttcut_v2_3.py` 放在一起。4K/60fps HEVC 的完整分析可能需要幾分鐘。

次級切分只檢查至少 6 秒的長候選；動作低谷至少要持續 1 秒，切分前後各保留至少 2.5 秒及雙側視覺活動，每個長候選最多兩個切點。這是供人工審核的初步規則，不保證所有場地或 ROI 都能正確分球。命令列 `--json` 會保留每個候選的 `splitChecks`，包含沒有採納的低谷與原因。

v0.2.2 會依時間順序審核每個低谷；音訊只降低短停頓的切分信心，不再一票否決強視覺證據。很短且證據較弱的候選仍保留在列表中，但會標示「低信心」，由使用者決定是否確認。展開候選的「檢查 valley」可查看每一個低谷的深度、持續時間、音訊扣分、切分信心與拒絕原因。

v0.2.3 保留上述偵測規則，改進預覽互動。低信心候選有黃色邊線與較大的「低信心 · 分數 · 請人工確認」標籤；按編號或候選區間只會暫停並跳到起點，按事件列會跳到該事件時間。只有 **確認發球** 會加入發球標記，A／B 得分仍由人工決定。

也可以只分析一小段做診斷：

```bash
python3 rally_detection.py match.MOV --roi 0.20,0.20,0.60,0.78 --start 30 --end 100 --json
```

`--roi` 依序是 `x,y,寬,高`，全部都是相對於整張畫面的 0–1 比例。

### 賽事精彩集錦 Builder

按上方 **建立賽事精彩集錦…**，選擇賽事根目錄。Builder 會遞迴掃描新版 `*/ttcut-data/*.tags.json` 與舊版直接放在比賽資料夾內的 `*.tags.json`，收集 point event 上的 `highlight: true`。沒有 Highlight 的比賽不列入編輯清單，但仍計入掃描場數；無關 JSON 會忽略，損壞的 tags JSON 與找不到 S 的 Highlight 會標出比賽與時間。

每球預設勾選，可取消並用 ↑／↓ 調整球序；比賽也可用 ↑／↓ 調整場次順序。點球列會從最近合法 S 的前 0.8 秒開始預覽，跨來源檔案時自動接到下一段。這些 Review 操作不會修改原本 tags JSON。

輸出是一支 MP4：3 秒賽事片頭後，依 Builder 畫面順序直接接上所有勾選的精彩球，不插入場次對戰卡；每球從原始來源渲染並使用與一般成片相同的計分推導，Koko 比分板在得分時間更新。片頭從目前第一個勾選精彩球的剪輯起點開始，直接使用約 3 秒自然動態原片；跨來源檔案時自動接續，片段不足 3 秒時定格最後一格補足。1280×720 JPG 封面取自同一段背景約 1.25 秒處。兩者都不套模糊、降亮度、降飽和度或黑色遮罩，並沿用一般比賽片頭／封面的等比例呈現規則；背景準備失敗時安全退回深色底。共同片源規格一致時保留解析度與 fps；規格混合時統一成 1920×1080、30 fps，保持比例並補邊，不拉伸。另輸出 `ttcut-data/*.highlights.json` Builder manifest。中間背景、片段、ASS、concat 清單都在系統暫存資料夾，完成或失敗後清除。

### 快捷鍵

| 按鍵 | 動作 | 按鍵 | 動作 |
| --- | --- | --- | --- |
| `space` | 播放／暫停 | `←` `→` | 逐格 |
| `S` | 發球 | `⇧←` `⇧→` | 一秒 |
| `A` | A 得分 | `⌥←` `⌥→` | 五秒 |
| `B` | B 得分 | `1` `2` `3` `4` | 0.5×／1×／1.5×／2× |
| `H` | 切換已選得分事件／最近完成回合的精彩球 | `Z` | 復原最後一筆 |
| `N` | 換局 |  |  |

點事件列表中的歷史得分列會跳到該時間並以橘色框選；此時 `H` 會切換該球。沒有選取歷史得分時，`H` 仍作用在已有 S 與 A/B 的最近完成回合；若目前只有 S，介面會要求先完成計分。開始新的候選／發球／得分操作會清除歷史選取，避免誤標舊球。得分列也可按有框線的星號按鈕直接切換，且不會觸發跳轉；已標記的列會顯示 `★ 精彩球`，上方同步顯示總數。按 `×` 可刪除事件。Highlight 直接存於該得分事件，例如 `{"t": 25.0, "type": "point", "winner": "B", "highlight": true}`；歷史選取只是介面狀態，不會寫入 JSON，舊 JSON 沒有 Highlight 欄位時視為零個精彩球。

## 賽制設定

| 設定 | 用途 |
| --- | --- |
| 每局 *n* 分 | 預設 11 分，要打舊制就填 21 |
| 標準／封頂 | 標準是要贏兩分。封頂制在 10:10 之後先到封頂分者勝，適合不想無限延長的球館規則 |
| 起始局數 | 一局一支影片、要接續前面局數時用 |
| 讓分 | 起始分數，可選每局套用或只套第一局 |

換發球是推導出來的，不用標：兩球換一次，deuce 之後每球換，新的一局由另一位先發。讓分的起始分不計入輪次，因為那幾分並沒有真的打。

## 數據統計看板

勾選 **數據統計** 之後，片尾會把最後一格畫面凍結住（預設 1 秒，可調），在中央疊上看板。角落的計分板會在此時收掉，把畫面讓出來；音軌同步補上等長的靜音，聲音和畫面長度不會對不上。

**上半部**是各局比分表，沿用轉播常見的排法：名字 → 總局數 → 各局分數。每一局贏的數字用亮色、輸的壓暗，總局數領先的一方用強調色。

**下半部**是左右對照：A 的數字在左、B 的在右，指標名稱置中。每一列比較好的一邊用強調色標出來。

| 指標 | 定義 |
| --- | --- |
| **總得分數** | 實際贏下的分數。讓分的起始分會顯示在計分板上，但不算在這裡——那不是打贏的。 |
| **發球得分率** | 自己發球時贏的分 ÷ 自己發球的分，原始分數寫在標籤旁邊。這是「由你開球時，你有多少把握」的數字。 |
| **最多連續得分** | 最長的連續得分，**跨局累計**。連兩局 11:0 就是 22，不是 11。 |

同一組數字在標記過程中就會即時顯示在右側欄，不必等算圖完才知道對不對。

有個前提值得記住：發球得分率的準確度完全取決於發球標記。漏標幾次 `S`，那幾分照樣算進總得分和連續得分，但輪次會跑掉，得分率也就跟著失真。

## 命令列

不想開介面、只想重算時用：

```bash
python3 ttcut_v2_3.py match.tags.json match.MOV
python3 ttcut_v2_3.py match.tags.json match.MOV --quality max --stats --stats-hold 3
python3 ttcut_v2_3.py match.tags.json match.MOV --dry-run      # 只印剪接表，不算圖
```

| 參數 | 預設 | 說明 |
| --- | --- | --- |
| `-o`, `--out` | `<影片>.cut.mp4` | 輸出路徑 |
| `--lead` / `--tail` | 讀 JSON | 發球前／得分後保留的秒數 |
| `--min-cut` | `2.5` | 短於此值就不剪，避免無意義的跳接 |
| `--cut-lets` / `--let-tail` | 關／`1.5` | 重發之間的撿球也剪掉 |
| `--stats` / `--no-stats` | 讀 JSON | 強制開啟或關閉統計看板 |
| `--stats-hold` | `1.0` | 看板停留秒數 |
| `--accent` | `#FF7A18` | 得分數字與名字左側裝飾條的顏色 |
| `--quality` | `high` | `fast`、`high`（標準，建議）、`max`（CPU libx264，非常慢） |
| `--encoder` | 依平台 | Mac 用 `h264_videotoolbox`；Windows 可用 `h264_nvenc`、`h264_qsv`、`h264_amf`、`libx264` |
| `--crf` / `--preset` / `--bitrate` | — | 直接覆寫畫質參數 |
| `--fps` | `source` | 預設跟著片源，也可以直接給數字 |
| `--hdr` | `auto` | `tonemap`、`keep`（需要 HEVC）、`ignore` |
| `--size` | 同片源 | 例如 `1920x1080` |
| `--hwaccel` | `auto` | Mac 用 `videotoolbox`，其餘 `none`、`cuda`、`qsv` |
| `--font` | 依平台 | 計分板名字用的字型 |
| `--ffmpeg` | — | `ffmpeg.exe` 的路徑或所在資料夾 |
| `--port` / `--no-browser` | — | 介面選項 |

完整清單請看 `--help`。

## 標記檔格式

匯出的就是純 JSON，可以直接手動改：

```jsonc
{
  "version": 2,
  "fps": 59.94,
  "players": { "A": "選手 A", "B": "選手 B" },
  "firstServer": "A",
  "format": { "pointsPerGame": 11, "deuce": "standard", "cap": 12 },
  "start": {
    "games":  { "A": 0, "B": 0 },
    "points": { "A": 0, "B": 0 },
    "handicapScope": "every"
  },
```

## 實作方式

- **剪接**用 ffmpeg 的 `select` 濾鏡篩選保留區間，而不是 `trim`+`concat`——後者會把整段解碼結果緩衝在記憶體裡。慢一些，但長片和 4K 不會爆掉。
- **計分板**產生成 ASS 字幕軌，再用 `subtitles` 濾鏡燒進畫面，所以任何解析度都能乾淨縮放，重畫也幾乎不花成本。
- **片尾凍結**是影像走 `tpad=stop_mode=clone`、音訊走 `apad`。
- **計分只有一份實作。** 瀏覽器完全不算分，它把事件丟給本機的 Python，再把回傳結果畫出來。只有一份邏輯，介面預覽和燒進去的計分板就不可能對不起來。
