# v3.0-C results

v3.0-C changes confidence metadata only. Candidate generation, temporal
segmentation, rescue, structural splitting, ROI handling, Review workflow
authority, and release gates remain unchanged. This note contains no source
paths or player names.

## Fixed evidence score

The score is deterministic, bounded to `[0, .99]`, and explicitly identified
as `ordinal_evidence_not_probability`:

```text
score = clamp[0,.99](
    .28
  + .26 * min(1, supportSeconds / 5)
  + .10 * min(1, strongSeconds / 3)
  + .20 * max(0, 1 - abs(sideBalance - .35) / .35)
  - .20 * clamp[0,1]((sideBalance - .60) / .30)
  + .12 * validatedSplit
  + .20 * validatedRescue
  - .50 * legacyStructuralPenalty
)
```

For coarse candidates, frame counts are converted at 2 fps. Dense rescue
candidates use their recorded rescue sample rate. Audio is not scored. A short
candidate receives no generic duration penalty, and a dense-validated rescue
can reach the high tier. Tiers are high `>=.75`, medium `.55-.74`, and low
`<.55`.

JSON keeps the previous value as `rawConfidence`, exposes the new value as
`confidence`, and adds `confidenceBasis` plus `confidenceTier`. The basis lists
component values, positive evidence, and cautions. Review remains manual; no
candidate is filtered or automatically rejected.

## Confidence quality

| Benchmark | ROC-AUC old -> new | Average precision old -> new | Brier old -> new | Median matched old -> new | Median unmatched old -> new |
| --- | --- | --- | --- | --- | --- |
| 01 | .532 -> **.700** | .586 -> **.778** | .266 -> **.214** | .710 -> **.695** | .675 -> **.555** |
| 02 | .538 -> **.693** | .720 -> **.839** | .218 -> **.191** | .740 -> **.740** | .750 -> **.560** |
| 03 | .308 -> **.739** | .684 -> **.885** | .219 -> **.163** | .710 -> **.740** | .750 -> **.560** |
| Aggregate | .496 -> **.712** | .654 -> **.829** | .235 -> **.192** | .710 -> **.730** | .740 -> **.560** |

The bottom quartile (43 candidates, maximum score `.53`) was 55.8% unmatched,
versus 32.4% overall, a 1.73x enrichment. It also contained 9 near-miss
predictions (20.9%) versus 23/170 (13.5%) overall. The transparent low tier
below `.55` contained 47 candidates, of which 27 (57.4%) were unmatched.

The score is not used as a detector threshold. For diagnostics only, the best
tested aggregate threshold was `.40`: precision/recall/F1 became
69.9/80.3/74.8%, versus 67.6/81.0/73.7% with every candidate. At `.55`,
precision rose to 78.9% but recall fell to 68.3%; the product deliberately does
not make that trade automatically.

The leave-one-benchmark-out robustness check produced held-scene ROC-AUCs
`.670`, `.686`, and `.717`; see the failure-analysis note for the selection
protocol.

## Detector invariance and runtime

Fresh source reruns used the same three ROIs/settings as B.

| Benchmark | Full-source candidates B / C | Start/end diff count | B runtime | C runtime | Delta |
| --- | ---: | ---: | ---: | ---: | ---: |
| 01 | 60 / 60 | **0** | 220.549s | 223.580s | +1.37% |
| 02 | 81 / 81 | **0** | 248.522s | 256.130s | +3.06% |
| 03 | 47 / 47 | **0** | 157.694s | 160.410s | +1.72% |
| Aggregate | 188 / 188 | **0** | 626.765s | 640.120s | +2.13% |

Because every interval is unchanged, TP/FN/unmatched, precision/recall/F1,
duration recall, merges, fragmentation, near misses, and nuisance counts remain
identical to B. Weighted realtime is **0.31284x**, below the 0.32x gate. The
confidence pass is linear in candidate count and adds no decode work;
wall-time differences are decode noise.
